Machine Learning Capstone · Research Paper

Ranking which content to refresh first: a data study of declining search pages

Machine Learning Track · Week 8 (ML-11) · Built on the FlyRank ML Internship dataset

Abstract

FlyRank builds content as infrastructure: it publishes pages for its clients, then watches search data and optimizes — yet every published page quietly decays over time, and with thousands of pages in play the decision that matters is which page should be fixed first.

This study asks whether a learned model can rank declining pages for that decision better than the transparent hand-written rule FlyRank already runs in production, using the FlyRank ML Internship dataset (30,000 pseudonymized content items across 32 clients, trailing-90-day search and engagement metrics; 54.2% labeled declining from an observed trend).

Method: a Random Forest ranker (18 numeric + 8 categorical features, no label-derived or identifier columns) is compared on the same client-holdout split against the baseline rule, with a grouped 5-fold robustness check.

On never-seen clients the model places 74% truly-declining pages at the top 50 of the queue vs 24% for the rule (base rate 54.2%) — a ~3× top-of-queue lift — with ROC AUC 0.75 vs 0.63.

The output is a decision-support review queue for FlyRank's optimization cycle — ranked, reason-tagged, human-gated — not a forecast of Google and not a promise that editing any single page will lift it.

1. Introduction / problem statement

FlyRank is content as infrastructure: it researches, writes, and publishes pages straight into a client's website, then watches search data and optimizes — the full cycle run by algorithms rather than people doing it by hand. The product already flags pages today with hand-written rules — if a page is visible but stale, or its position is slipping, a threshold trips. Those rules work and run in production, but they are a fixed lens: they cannot weigh visibility, staleness, position, and engagement all at once the way a trained model can. That gap — a learned model where a fixed rule currently lives — is exactly where this capstone sits.

Concretely, the decision in one scenario: an editor opens a dashboard holding 30,000 pages and must choose which one to review first. A wrong call means editing the wrong page while the right one keeps sliding — a wasted hour and a missed decline. This is a ranking problem on messy, real search data, which is where a learned model can beat a fixed rule.

The question this paper answers: does a model trained on observed signals rank declining pages at the top of a reviewer queue better than the existing rule, and is the gain honest when validated on never-seen clients? The unit of analysis is the content page; the output is a 0–100 refresh score; the human action is "open this page and decide"; the cost of a wrong call is wasted editorial effort or a missed decline.

2. Data

Release. The bundled anonymized starter release of the FlyRank ML Internship dataset: data/raw/content_refresh_anonymized.csv — one row per pseudonymized content item.

  • Size: 30,000 rows × 44 raw columns (52 after feature prep), covering 32 pseudonymized clients.
  • Time window: all metrics are aggregates over a single trailing-90-day window ending at export time; 30-day comparison windows (last vs previous) drive the trend label.
  • What is measured: search impressions/clicks and position (Google Search Console), sessions/pageviews/engagement and AI-referred sessions (Google Analytics), plus content metadata — age, freshness, word/char counts, keyword context (search volume, competition, CPC), and derived rates.
  • Public-safe exclusions: the export ships no client names, domains, URLs, page titles, keywords, or raw queries. Only hashed pseudonymous IDs (content_id / client_id) remain, used for grouping and splitting only — never as features.

Label source. The target is_declining_label is derived from trend_direction == "down", itself computed from the last-30d vs prev-30d impressions comparison (16,262 of 30,000 rows, 54.2% base rate).

3. Methodology

Assumptions

  • Observed decline in this snapshot is a fair proxy for "worth an editor's time"; we rank it, we do not forecast it.
  • Rate columns are percentages on a 0–100 scale (ctr = 0.76 means 0.76%), and avg_position = 0 means "no position data", not rank zero — we add a has_position_data-style flag rather than imputing blindly.
  • Missingness is systematic by content type, so indicators beat blind fillna(0).

Features

18 numeric + 8 categorical features, defined in one place (scripts/ml_utils.py): visibility and reach (log_impressions_90d, log_clicks_90d, days_with_impressions), position (avg_position, position_tier), staleness and age (content_age_days, days_since_last_update, age_tier, freshness_tier), engagement (ctr, scroll_rate, engagement_rate, ai_traffic_pct), article shape (word_count, char_count, word_count_tier), and keyword context (search_volume, competition, competition_level, main_intent, content_type).

Label definition

One sentence: a page is labeled declining (1) when its observed last-30d impressions dropped ≥20% versus the prior 30 days (trend_direction == "down"), else 0.

Baseline

The Week-4 transparent rule: a hand-written threshold score (visibility, staleness, position rules) that produces the same ranked queue, evaluated on the same held-out clients and the same metric.

Validation design

Because pages from one client share a publisher, cadence, and query mix, a random row split would let the model memorize clients. We split by client: hold out ~20% of the 32 clients (6) entirely, train on the remaining 27,675 rows, evaluate on 2,325. A grouped 5-fold (every client held out once) is run as a robustness check and reported alongside.

Leakage checks

  • trend_direction, trend_pct, and both 30-day comparison windows that compute the label are never features.
  • content_id / client_id are grouping/splitting only, never features.
  • All three leakage classes (label-derived siblings, overlapping windows, existing product flags) were audited; the product's own decision flags (health_score, etc.) are not even shipped in the release.

What the model leans on

Feature importances show decline is read from visibility, reach, age, and position — not from the label's own columns. The top drivers are how many days a page appeared in search, its total impressions, its average position, and how old it is.

Honesty check: the out-of-group estimate

One holdout fold is hostage to which clients drew the short straw. A grouped 5-fold in which every client is held out once gives the sober numbers: precision@50 ≈ 0.6 (vs 0.54 base rate), precision@10 ≈ 0.5, average precision ≈ 0.68. The single-holdout 0.74 at P@50 is therefore best read as an upper estimate; the repeatable claim is a directional 1.5–3× lift at the top of the queue depending on K.

5. Limitations & honest framing

  • Observational, not causal. We rank pages that were observed declining in one snapshot. Nothing here proves that refreshing a page lifts it — no controlled experiment was run. Refreshing is a recommendation, not a measured effect.
  • Not a forecast. The model does not predict Google's algorithm. It generalizes across held-out clients in this release; the future is unobserved.
  • Weakest at the very top. The first ~10 rows of the queue are only ~50% precise — the pages that seem most urgent need the most careful human eyes.
  • Thin, noisy low-position pages. Pages buried in search carry the noisiest measurements; the model misses most true declines there (its deepest error cell).
  • No position data is not rank zero. 1,205 rows with avg_position = 0 cannot be judged on rank and stay in "monitor" for human eyes only.
  • Single snapshot, single release. One 90-day window and one anonymized slice; results are directional until re-run on fresh data with the drift triggers below.

6. Ranked recommendations (action playbook)

Scored with the validated model and tagged with a reason and a plain action, the 30,000 pages split into a reviewable queue:

  • 1. Start with the 3,602 high-confidence pages. These are visible-and-declining pages the rule and model agree on. An editor opens each, confirms the reason code is real, and edits. This is where measured precision is highest (≈70% within rule-flagged pages).
  • 2. Within them, refresh + review CTR first. 6,654 pages are "refresh and review CTR" (visible, low-CTR, declining) — the biggest actionable band; the top of the queue is dominated by refresh_and_review_ctr. Then the 1,993 "refresh and review engagement" pages.
  • 3. Target the 91–180-day untouched pool. Among visible pages untouched for a quarter, 62% were observed declining (n=6,558) — the largest measurable decay pool. Stale-visible pages get refresh.
  • 4. Let reason codes route the work. The mix: monitor 13,083 · refresh 8,188 · refresh+review CTR 6,654 · refresh+review engagement 1,993 · expand 82.
  • 5. Keep a human gate on everything. Read, don't run: no auto-edit, no auto-publish; 339 visible declining top-3 pages are frozen behind sign-off; no verdict on pages without position data; no client-facing claim from one snapshot.
  • 6. Watch the drift triggers. Retrain if the next snapshot's precision@50 drops below 0.55, the base rate leaves 54–59%, the top-10% score threshold moves ±3pts, or any input column changes meaning.
